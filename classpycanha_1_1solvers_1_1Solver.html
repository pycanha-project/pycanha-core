Detailed Description

Base of every solver type.

A solver works on one model with one Settings. initialize() resolves the settings (see resolve()), warns once about the set fields that do not apply, and builds everything the solver needs; solve() runs it. The INIT settings are frozen while the solver is initialised; the LIVE ones are read again at every solve().

solve() throws ModelChangedError when the model's nodes or coupling patterns changed since initialize(), checked at the start and after every callback. An iteration loop that stops at max_iterations logs one WARN (and, in a transient, one summary WARN at the end); report() has the details.

◆ auto_configure()

Settings pycanha::solvers::Solver::auto_configure ( std::optional< std::int64_t > max_memory = std::nullopt)

Chooses the storage, backend, factorization, reuse_factors, threads, pardiso.ordering, pardiso.level and eigen.ordering for the current model, clears pardiso.iparm, and returns the new settings. The other settings are kept. The candidates, in order of preference:

Solver # With MKL Without MKL
SteadyState 1 DENSE LAPACK, reuse (rule S) DENSE EIGEN
SteadyState 2 PARDISO TWO_LEVEL ND EIGEN COLAMD
SteadyState 3 PARDISO ONE_LEVEL MD EIGEN AMD
CrankNicolson 1 DENSE LAPACK, reuse (rule T) DENSE EIGEN
CrankNicolson 2 PARDISO ONE_LEVEL MD, reuse EIGEN COLAMD
CrankNicolson 3 PARDISO TWO_LEVEL ND EIGEN AMD
JacobianPropagation 1 DENSE LAPACK (rule T) DENSE EIGEN
JacobianPropagation 2 PARDISO TWO_LEVEL ND EIGEN COLAMD
JacobianPropagation 3 PARDISO ONE_LEVEL MD EIGEN AMD

Candidates 2 and 3 are SPARSE; ND is NESTED_DISSECTION, MD MIN_DEGREE and "reuse" reuse_factors = true. Candidate 1 exists only when its rule holds, with n the diffusive nodes and a coupling a conductive or radiative link between two of them:

  • rule S: n <= 5000 and at least 100 couplings per node on average;
  • rule T: n <= 2000 and at least 20 % of the n x n matrix filled. Dense storage wins where nodes see hundreds of others: it needs no analysis, and the sparse factors of such a matrix are nearly dense anyway. Rule T is stricter because a sparse transient does its analysis once for all its steps.

Every candidate sets factorization = AUTO (Cholesky without radiative couplings, except with sparse Eigen; LU otherwise) and, with MKL, threads = 0. reuse_factors iterates on the previous factors (PARDISO CGS, or CG for Cholesky; LAPACK FGMRES) and refactorizes only when that fails. It needs MKL and never applies to JacobianPropagation, whose sensitivity solve needs the factors of the current matrix. A steady state without it still solves an unchanged matrix with the existing factors. The PARDISO minimum degree analysis is done once, but can take long on models where a few nodes are coupled to many.

Without max_memory the first candidate is taken. With max_memory [bytes], a candidate whose estimate_memory() exceeds it is skipped, and when none fits the smallest is taken with a WARN. Throws std::runtime_error on an initialized solver.

◆ estimate_memory()

SolverMemory pycanha::solvers::Solver::estimate_memory ( )
nodiscard

The memory this solver needs for the current model and settings.

Without an initialized solver it builds the matrix pattern and runs the analysis of the factorization (see SolverMemory::exact for which figures are known and which predicted), and a following initialize() with the same settings and model structure reuses that work. On an initialized solver it gives the current figures. Throws std::invalid_argument for contradictory settings and std::runtime_error when the analysis fails.
